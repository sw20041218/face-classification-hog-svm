# ResNet50 迁移特征双 SVM 分数融合

本地人工标注开发集正确 408/420，ACC=0.97142857。后续 platform_feedback.json 记录用户反馈的平台 ACC 为 0.962（96.2%），未通过平台接口独立核验；不能将本地 97.1429% 写成平台成绩。

输入为原始 19×19 灰度图，双线性放大至 96×96 并复制三通道，使用 ImageNet 标准化。冻结 ResNet50，提取 layer2 的 2×2 池化特征 2048 维、layer3 的 2×2 池化特征 4096 维和 layer4 的全局池化特征 2048 维；各层分别 L2 归一化，拼接后再归一化，形成 8192 维迁移特征。传统特征为 361 维对比度与 324 维 HOG，共 685 维。

两个分支都把传统特征与加权迁移特征拼接并 L2 归一化，分别训练一个 RBF-SVM：

- A：迁移特征幅度系数 0.25，C=1，gamma=2。
- B：迁移特征幅度系数 2，C=0.1，gamma=2。

每个 SVM 只使用原训练集 800 张及其水平镜像拟合，每个版本权重 0.5。推理时平均原图与镜像决策分数，得到 sA、sB。最终分数为 0.4*sA/0.5528784826353844 + 0.6*sB/0.47635442672991823。分数大于 -1.5875983196170376 输出 +1，否则输出 -1。分数标准差是开发集分数上计算并固定的缩放常数，不是概率校准。

本轮确实采用两个分类器融合，不再是单个 SVM。人工测试标签参与配置、融合权重及阈值选择，因此本地成绩属于经过反复调参的开发成绩。没有把测试样本加入 SVM 拟合，没有按图片编号手工覆盖预测。预训练网络使用外部 ImageNet 权重，与上一轮迁移特征方案保持同类边界。

search.py 保存单模型搜索，fusion.py 搜索双模型融合，finalize.py 重新训练最终两模型、保存后重新加载核验输出。ensemble_model.joblib 保存两个 SVM、训练融合特征与融合配置，公开 verification.json 仅保存汇总与文件哈希，不包含逐样本错分编号。特征缓存和提取脚本位于相邻 transfer_search_20261114 文件夹。

result_transfer097.txt 为提交文件，共 420 行，连续编号 1 至 420，格式为编号、一个 ASCII 空格、整数标签、LF 换行。不要将旧 result_097.txt 作为本轮最终文件；它是搜索过程中保留的单模型候选。

## 公开模型格式

原 ensemble_model.joblib 含两份 1600×8877 的训练融合特征，约 179 MB。公开副本保留原 SVM、配置、融合权重、标准差和阈值，仅删除重复 train_features；推理时由 train_data.mat 与缓存重建原特征。公开模型约 10 KB，已验证 420 条预测及文件哈希与原提交完全一致。它不是原模型文件的逐字节副本，需要使用本轮 predict_ensemble.py，不可直接按旧格式读取 train_features。

单模型候选 model.joblib 约 114 MB，非最终提交模型，未上传，可由 search.py 再生成。result_097.txt 是其候选结果；最终文件是 result_transfer097.txt。特征缓存 resnet50_96.npz 与完整搜索所需 resnet18_160.npz 已补入相邻 transfer_search_20261114；缓存仅包含图像特征，没有人工标签。

## 运行顺序

无标签直接推理：`python transfer_target097/predict_ensemble.py --output prediction_transfer097.txt`。仅适用于仓库原 420 个样本和匹配缓存，换图需重提特征。无需 PyTorch 或人工标签，使用 requirements.txt 即可。

完整开发流程：依次运行 search.py、fusion.py、finalize.py，每条命令均需 `--labels "PATH/TO/private_labels.mat"`。文件内变量为 test_label，顺序对应现有 420 个样本。标签不在仓库，不能只凭公开文件复算开发集评价。训练流程会覆盖模型、日志、预测，但不会更新历史平台反馈。

search 日志实际含 864 条评价，对应 432 次 SVM 拟合及原图/镜像平均、原图两种推理；包括三种特征来源、六种融合设置、六种 gamma、四种 C。本轮单模型最优为 405/420。随后先按来源/权重/推理组各取正确数最高的两个候选，再搜索两两融合权重 0.2/0.4/0.6/0.8，并用人工开发标签选阈值，最终达到 408/420。融合中的标准差来自开发集分数，是确定后冻结的尺度，不是概率。

仓库把外部标签路径改成显式必填参数；fusion.py 对原 set 遍历改为排序以稳定顺序，同分候选可能与原未排序执行选中不同组合，历史 fusion_best.json 保留原选定结果。finalize.py 保存精简格式并不再输出逐样本错分列表。原报告与生成脚本不纳入本次发布；原核验中的错分、纠正/退化编号列表全部从公开副本移除，避免结合预测还原人工标签。

原核验引用的上轮 baseline 文件哈希与仓库上轮文件版本可能不同，不能直接沿用其 406/420 或“提升几张”的结论评价当前仓库基线。此次最终两模型重训通过，输出 408/420 和最终提交哈希一致；没有重跑 432 次候选拟合或神经网络提取。
